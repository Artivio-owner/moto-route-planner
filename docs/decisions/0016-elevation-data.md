# ADR-0016: Данные высот для профиля маршрута

- **Статус:** Принято разработкой (2026-10-28); источник и лицензию владелец может пересмотреть.
- **Дата:** 2026-10-28
- **Задача:** E-01 (источник и лицензия), профиль высоты в PDF (X-06, блок 6; владелец: «все блоки, включая профиль высоты»).

## Контекст
Для профиля высоты нужны высоты точек маршрута. GraphHopper 11 умеет брать их из цифровых моделей рельефа при сборке графа и отдавать в ответе (`elevation: true`). Платные API высот не подключаем (правило CLAUDE.md).

## Варианты
| Вариант | Покрытие | Лицензия | Минусы |
|---|---|---|---|
| `srtm` (SRTM3, зеркало srtm.kurviger.de) | до 60° с. ш. | данные NASA SRTM: общественное достояние (зеркало и его условия не проверены) | Север России (Архангельск, Якутия, Чукотка) без данных: высота 0 м |
| `gmted` (GMTED2010, USGS) | весь мир | общественное достояние (USGS) | грубее (около 250 м на точку) |
| **`multi`** (CGIAR SRTM до 60°, GMTED2010 севернее) | весь мир | CGIAR-CSI: бесплатно для некоммерческого использования; GMTED: общественное достояние | Условие «некоммерческое» (как у Open-Meteo) |

## Решение
`multi` по умолчанию (`infra/graphhopper/config.yml`): нужен весь мир (ADR-0006), а сервис бесплатный и некоммерческий (ответ 1). Если условие CGIAR станет проблемой (например, из-за регулярных донатов, W-06), переключить на `gmted` одной строкой в конфигурации и пересобрать граф.
Профиль показываем, только если сервер отдаёт высоты: без них раздел в PDF и набор высоты в путевом листе не выводятся.

## Последствия
- Файлы высот скачиваются при первой сборке графа в том `elevation-cache` (docker-compose). Объём и время для России не измерены (S-03).
- API упрощает линию с учётом высоты (допуск 10 м), чтобы перевалы на прямых дорогах не терялись.
- В CI граф собирается с тестовыми файлами SRTM (`infra/graphhopper/test/make_srtm.py`), скачивания нет.
- Не проверено: доступность источников CGIAR и GMTED с сервера владельца, условия зеркала srtm.kurviger.de, точность в горах.
