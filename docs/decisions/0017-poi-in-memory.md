# ADR-0017: АЗС и жильё вдоль маршрута без отдельной базы

- **Статус:** Принято разработкой (2026-10-28)
- **Дата:** 2026-10-28
- **Задачи:** P-01 (АЗС), P-02 (отели и кемпинги), P-05 (импорт POI), P-07 (выборка вдоль маршрута), C-02 (заправки по реальным АЗС); v0.3 (ADR-0012).

## Контекст
В `docs/03-tech-stack.md` для POI предлагался PostGIS с регулярным импортом (P-05). Нужно только два слоя: АЗС и жильё, и только вдоль построенного маршрута.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| PostGIS + импорт | Гибкие запросы, любые слои | Ещё один сервис, память, резервные копии, миграции |
| Overpass API (внешний) | Ничего не хранить | Чужой сервис с ограничениями нагрузки; зависимость от него для каждого маршрута |
| **Файл GeoJSONSeq + индекс в памяти API** | Без новых сервисов; один шаг в `prepare-data.sh`; быстрый поиск по сетке | Только простые слои; обновление вместе с данными OSM |

## Решение
Файл в памяти API. `infra/scripts/extract-pois.sh` (osmium-tool) вырезает из той же выгрузки OSM `amenity=fuel` и `tourism=hotel,motel,guest_house,hostel,camp_site,chalet`; API (`POI_FILE`) держит точки в сеточном индексе 0,1°. В ответе маршрута поле `pois`: АЗС до 1 км и жильё до 5 км от линии, с километром маршрута и удалением.
Расчёт ставит заправки на самые дальние АЗС в пределах запаса хода и отмечает участки, где АЗС дальше запаса. В путевом листе и PDF: число АЗС на участке дня и до трёх вариантов ночлега у финиша дня; на карте точки видны с приближения 8.
Без файла сервис работает как раньше (заправки через каждый запас хода).

## Последствия
- PostGIS не нужен; задача P-05 закрыта этим решением. Если понадобятся сложные слои (мотодома, свой мотослой P-06), вернуться к PostGIS новым ADR.
- Данные OSM: атрибуция ODbL уже есть в интерфейсе и PDF.
- Не проверено: число точек и память для России (S-04, оценка: десятки тысяч точек, единицы-десятки МБ), полнота тегов АЗС и жилья в России.
