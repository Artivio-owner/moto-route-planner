# ADR-0010: Без кабинета администратора, конфигурация как код

- **Статус:** Отклонено владельцем 2026-10-21 («Админка нужна»), заменено ADR-0013. Хранение настроек в `data/` со схемами сохраняется
- **Дата:** 2026-10-21

## Контекст
В сервисе есть данные, которые нужно настраивать и обновлять: цены по умолчанию (топливо по странам, жильё, еда, кофе), курс доллара, пресеты профилей мотоцикла, пороги предупреждений (закат, погода, дневная нагрузка), список стран и регионов покрытия, тексты лендинга и FAQ, контакты. Аккаунтов у пользователей нет (ADR-0005), команда маленькая, проект открытый и бесплатный.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Конфигурация как код** (файлы в репозитории, изменения через Pull Request, проверка схемой в CI, автодеплой) | Нет серверной части для админа, нет паролей и поверхности атак, история изменений в Git, подходит открытому проекту и работе через Claude Code | Менять данные нужно через GitHub: для нетехнического человека неудобно |
| **B. Своя админка** (вход владельца, редактирование значений в БД) | Удобный интерфейс | Нужны авторизация, хранилище, резервные копии, защита: больше кода и рисков; противоречит идее «без серверного состояния» |
| **C. Git-CMS поверх репозитория** (редактор с интерфейсом, который коммитит в GitHub) | Удобно владельцу, данные остаются в репозитории | Нужен вход через GitHub и небольшая настройка; не проверялось, подходит ли под наш хостинг |

## Предложение
Для MVP вариант **A**. Файлы настроек в `data/`: `fuel-prices.json`, `lodging-defaults.json`, `food-levels.json`, `moto-presets.json`, `warning-thresholds.json`, `countries.json`, `exchange-rate.json`, тексты в `content/`. В CI проверка схемы и осмысленности значений. Если правки станут частыми или появится нетехнический редактор, перейти на вариант C, не на B.

## Последствия
- Изменение цены или текста идёт через PR (владелец или Claude Code), сразу видна история.
- Курс доллара и цены на топливо меняются часто: без админки они устареют, если их не обновлять. Нужно решить, кто и как часто обновляет, или найти автоматический источник (не проверялось).
- Модерация предложенных точек и обратная связь идут через GitHub Issues, а не через кабинет.
- Операционные вещи (перезапуск, логи) решаются средствами хостинга и не считаются частью продукта.
