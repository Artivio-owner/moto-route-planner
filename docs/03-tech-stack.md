# Технический стек и архитектура (предложение)

> Статус: **предложено**, утверждается через ADR-0002 после спайков S-01 и S-02.

## Принципы
- Открытые данные и открытое ПО, без зависимости от платных API в ядре.
- Один язык (TypeScript) на фронтенде и бэкенде.
- Модульный монолит, а не микросервисы: команда небольшая.
- Всё воспроизводимо через Docker Compose.

## Компоненты
| Слой | Выбор | Альтернативы | Почему |
|---|---|---|---|
| Фронтенд | TypeScript, React, Vite | Svelte | Большая экосистема |
| Карта | MapLibre GL JS | Leaflet | Векторные тайлы, открытая лицензия |
| Тайлы | Свои векторные тайлы из OSM (Protomaps / OpenMapTiles) | MapTiler | Независимость от внешних лимитов |
| Бэкенд | Node.js, Fastify, TypeScript | Python FastAPI | Один язык со фронтендом |
| БД | PostgreSQL + PostGIS | SQLite для прототипа | Гео-запросы по POI (v0.3); маршруты на сервере не храним (ADR-0005) |
| Маршрутизация | **GraphHopper** (self-hosted) с мото-профилем | Valhalla, OSRM | Гибкие custom-модели; нужна проверка кривизны (спайк S-01) |

| Экспорт | GPX 1.1 на сервере | | Универсальный формат |
| CI/CD | GitHub Actions | | Репозиторий уже на GitHub |
| Развёртывание | Docker Compose, VPS | Kubernetes | Достаточно для MVP |

## Архитектура (упрощённо)
Браузер (React + MapLibre) → API (Fastify) → GraphHopper (маршрут) / Photon (адреса) / PostGIS (POI) / расчётный модуль (топливо, дни, бюджет). Состояние маршрута живёт в браузере и в ссылке (ADR-0005); настройки читаются из `data/` (ADR-0013).

Расчёты топлива, дней и бюджета держим в **чистом модуле без зависимостей** (`packages/calc`), чтобы они тестировались юнит-тестами и работали и на сервере, и в браузере.

## Структура кода (план)
```
apps/web        # фронтенд
apps/api        # бэкенд
packages/calc   # топливо, дни, бюджет
packages/shared # типы
infra/          # docker-compose, конфиги GraphHopper
```

## Данные и лицензии
- OpenStreetMap: лицензия ODbL, нужна атрибуция «© участники OpenStreetMap» на карте и в страницах экспорта.
- Выгрузка РФ: Geofabrik или аналог; объём и требования к серверу уточнить в спайке.
- Мото-POI в MVP: только из OSM. Базу точек moto.tours не используем.

## Риски
| Риск | Влияние | Митигация |
|---|---|---|
| Серверу не хватит памяти для обработки OSM по России | Нельзя собрать граф маршрутов | Спайк на меньшем регионе, затем масштабирование |
| Кривизна дорог не поддерживается нужным образом | Нет режима «извилистые» | Спайк S-01, запасной вариант: Valhalla или свой расчёт |
| Качество OSM по грунтовым дорогам неравномерное | Ошибки маршрутов | Предупреждения, возможность править точки вручную |
| 152-ФЗ | Аккаунтов нет (ADR-0005), риск низкий | Юридические тексты по шаблону (решение владельца) |
