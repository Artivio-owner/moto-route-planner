# Спецификация: PDF путевой лист

Дата: 2026-10-21. Статус: состав утверждён владельцем: **все блоки 1–9** (включая графики: километраж по дням, структура бюджета, уровень топлива, профиль высоты). Приоритет P0 (ядро продукта, ответы 9 и 22).

## Цель
Пользователь задаёт условия (маршрут, даты, люди, мотоцикл, жильё, валюта) и скачивает максимально подробный PDF: всё, что обычно считают вручную.

## Состав документа
1. **Титул:** название маршрута, даты, число людей, профиль мотоцикла, валюта, дата расчёта.
2. **Сводка:** километры, дни, часы в седле, литры, заправки, бюджет по статьям, итог.
3. **Общая карта** маршрута на тайлах OSM с границами дней и пунктами ночёвки.
4. **Таблица по дням:** дата, откуда и куда, километры, время, заправки, закат, погода или климат, ночёвка, стоимость дня.
5. **Детали по дням:** карта дня (P1), АЗС и жильё из OSM вдоль участка, предупреждения (закат, нехватка топлива, превышение лимитов).
6. **Графики:** километраж по дням, структура бюджета, уровень топлива по маршруту, профиль высоты (если подтвердим данные высот).
7. **Бюджет:** формулы и допущения, цены, которые изменил пользователь.
8. **Погода:** прогноз на ближайшие до 16 дней, дальше климатическая норма с пометкой.
9. **Источники и атрибуция:** © участники OpenStreetMap, Open-Meteo (CC BY 4.0), оговорка «расчёты ориентировочные».

## Критерии приёмки
- Given рассчитанный маршрут Сочи — Москва — Владивосток When жму «Скачать PDF» Then получаю файл, где есть все разделы 1–9, кириллица отображается корректно.
- Given пользователь изменил цену жилья When формирую PDF Then изменённое значение помечено.
- Given маршрут на 1 день When формирую PDF Then нет разделов про ночёвки, остальное корректно.
- Given дата поездки дальше 16 дней When формирую PDF Then вместо прогноза климатическая норма с пометкой.
- Файл открывается в стандартных просмотрщиках; размер разумный (цель: до 10 МБ для 21 дня, уточнить).

## Варианты реализации (нужен спайк S-05)
| Вариант | Плюсы | Минусы |
|---|---|---|
| Сервер: headless-браузер печатает HTML в PDF | Единый стиль с сайтом, проще вёрстка | Нужны ресурсы сервера |
| Сервер: библиотека для PDF (WeasyPrint, ReportLab) | Легче по ресурсам | Графики и карты сложнее |
| Клиент: сборка PDF в браузере | Не нужен сервер под PDF | Тяжёлые маршруты, различия браузеров |

Стиль PDF: палитра и шрифт Rubik из `docs/design/design-system.md`.

Общие требования: встроенные кириллические шрифты с открытой лицензией; карта на наших тайлах (Яндекс запрещает скриншоты, ADR-0004); без хранения маршрутов на сервере (ADR-0005).

## Реализация v0.1 (2026-10-26)
- Собирается в браузере: ADR-0014. Код: `apps/web/src/pdf/`.
- Есть: 1 титул, 2 сводка, 3 карта (снимок MapLibre или векторная схема), 4 таблица по дням (местное время с поясом, заправки, топливо, платные участки, паромы, предупреждения), график километража по дням (из блока 6, раньше плана), 9 источники и оговорки, номера страниц.
- Будет в v0.2–v0.3 (ADR-0012): бюджет, погода и закат, детали по дням с POI, профиль высоты, график топлива.
- Имя файла `versta_откуда-куда_дата.pdf` (вопрос 31).

## Реализация v0.2–v0.3 (2026-10-28)
- Графики: структура бюджета (полоса с долями статей) и уровень топлива по маршруту (полный бак на старте, заправки до полного через запас хода, линия резерва 10%).
- Карты по дням: по две в ряд, снимок на наших тайлах для первых 30 ходовых дней, дальше схема; если снимок не получился (нет WebGL или тайлов), все дни рисуются схемой, чтобы PDF не собирался долго.
- Осталось: профиль высоты (E-01: источник данных высот и лицензия), АЗС и жильё по дням (P-07: нужна выборка POI вдоль маршрута).
