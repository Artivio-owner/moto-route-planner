# Спецификация: разбивка маршрута по дням

Дата: 2026-10-20. Статус: черновик. Связано: [02-prd-mvp.md](02-prd-mvp.md) (P0-5), [07-budget-spec.md](07-budget-spec.md).

## Зачем
Мотопутешествие на несколько дней нужно разделить на дневные отрезки: где ночевать, сколько ехать в день, успеем ли до темноты, сколько это стоит. У конкурента есть дробление по промежуточным точкам, по часам и по километрам. Мы добавляем выбор по числу дней и самостоятельный выбор мест отдыха «от города до города».

## Режимы дробления
| Режим | Что задаёт пользователь | Что делает система | Приоритет |
|---|---|---|---|
| **По километрам** | «Не более N км в день» | Режет маршрут на отрезки не длиннее N км | P0 |
| **Вручную, от города до города** | Сам выбирает пункты ночёвки (города или точки на карте) | Считает каждый день как отрезок между выбранными пунктами | P0 |
| **По времени в пути** | «Не более N часов в седле в день» | Считает время по скоростям классов дорог и остановкам, режет по лимиту | P1 |
| **По числу дней** | «Хочу уложиться в N дней» | Делит маршрут на N примерно равных по времени дней | P1 |

Режимы взаимоисключающие, переключаются в настройках маршрута. После автоматического дробления пользователь может подвинуть любую границу дня или перейти в ручной режим.

## Общие правила
- **Привязка к населённым пунктам (P1).** Автоматическая граница дня не должна оказываться «в поле». Система ищет ближайший подходящий населённый пункт (по данным OSM) около расчётной точки и предлагает ночёвку там. Допуск по умолчанию: в пределах 10% дневной нормы; значение уточняем на практике.
- **Дневка (P1).** Пользователь может отметить день отдыха в городе: ночь, еда и жильё считаются в бюджете, километраж равен нулю.
- **Время в пути** включает ходовое время по классам дорог и остановки на заправки (число заправок из расчёта топлива) и отдых; длительность остановок задаётся параметрами с значениями по умолчанию.
- **Предупреждения по каждому дню:**
  - дневной километраж или время превышают заданный лимит;
  - день заканчивается после захода солнца (нужны дата старта и расчёт восхода и заката);
  - не хватает топлива до ближайшей АЗС;
  - неблагоприятная погода на участке (P1, когда подключена погода).
- **Дата и время старта дня:** по умолчанию общий старт из настроек маршрута; для каждого дня можно изменить.

## Что видит пользователь по каждому дню
Дата, откуда и куда, километры, время в пути, число заправок, стоимость топлива, погода (P1), время заката, предложения жилья из слоёв POI (P1), статьи бюджета.

## Связь с бюджетом
- **Число ночей = число пунктов ночёвки** (дни пути минус 1, плюс дневки). Ночь в конечной точке добавляется переключателем.
- Еда считается на число дней, включая дневки.
- Кофе на заправках считается от числа заправок по дням.

## Критерии приёмки
**По километрам (P0)**
- Given маршрут 900 км и лимит 300 км в день When выбираю режим «по километрам» Then получаю 3 дня по 300 км или меньше, границы видны на карте и в списке.
- Given лимит больше длины маршрута When считаю Then получаю 1 день без ночёвок.

**Вручную (P0)**
- Given маршрут из Москвы в Сочи When добавляю ночёвки в Воронеже и Ростове-на-Дону Then получаю 3 дня: Москва — Воронеж, Воронеж — Ростов, Ростов — Сочи, для каждого км и время.
- Given удаляю пункт ночёвки When пересчитываю Then дни объединяются, итоги и бюджет обновляются.
- Given выбранный пункт не лежит на маршруте When добавляю Then маршрут перестраивается через него, пользователь видит изменение.

**По времени (P1)**
- Given лимит 8 часов в седле When считаю Then ни один день не превышает 8 часов с учётом остановок на заправки.

**По числу дней (P1)**
- Given выбираю 4 дня When считаю Then дни примерно равны по времени (отличие не более 15%, значение уточняем).

**Предупреждения (P1)**
- Given день заканчивается после захода солнца When показываю итоги Then у дня есть предупреждение с временем заката и подсказкой сдвинуть старт или ночёвку.

**Дневка (P1)**
- Given отмечаю дневку в городе When считаю бюджет Then добавляется ночь и еда, километраж дня равен 0.

## Технические заметки
- Дробление выполняет модуль `packages/calc` по геометрии маршрута: он принимает отрезки с длиной, временем и классом дороги и возвращает границы дней. Модуль без зависимостей, покрывается юнит-тестами.
- Для режимов по времени нужны классы дорог по участкам от движка маршрутизации: проверяем в спайке S-01.
- Привязка к городам использует населённые пункты OSM (`place=city/town/village`) в выборке вдоль маршрута (задача P-07).
