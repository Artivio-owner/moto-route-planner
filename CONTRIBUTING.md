# Как мы работаем

## Единый источник правды
- Задачи: **GitHub Issues** + [BACKLOG.md](BACKLOG.md) (обзор приоритетов; при расхождении верен Issue).
- Решения: [docs/decisions/](docs/decisions/) (ADR). Любое решение, которое трудно откатить, получает ADR.
- Процесс и ход работ: [docs/process/worklog.md](docs/process/worklog.md) — запись после каждой рабочей сессии.

## Цикл работы
1. Идея или проблема → Issue по шаблону.
2. Приоритизация (P0/P1/P2, при спорах RICE) → строка в `BACKLOG.md`.
3. Планирование спринта → `docs/sprints/sprint-NN.md`.
4. Разработка в ветке, Pull Request по шаблону.
5. Ретро спринта → раздел «Итоги» в файле спринта + запись в worklog.

## Ветки и коммиты
- `main` защищена, изменения только через PR.
- Ветки: `feat/<issue>-кратко`, `fix/<issue>-кратко`, `docs/<кратко>`.
- Коммиты в стиле Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`.

## Приоритеты
- **P0** — без этого MVP не выпускаем.
- **P1** — быстро после MVP.
- **P2** — на будущее, учитываем в архитектуре.

## Definition of Done
- [ ] Код отревьюен и влит в `main`
- [ ] Тесты проходят в CI
- [ ] Документация и `BACKLOG.md` обновлены
- [ ] Критерии приёмки из Issue выполнены
- [ ] Запись в worklog

## Правила по контенту и данным
- Свой код, свои тексты, свой дизайн. Не копируем код, тексты, графику и базу точек интереса сторонних сервисов (см. ADR-0003).
- Источники данных и их лицензии фиксируем в `docs/03-tech-stack.md` (раздел «Данные и лицензии»).
